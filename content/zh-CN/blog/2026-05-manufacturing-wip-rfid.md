## TL;DR

制造业车间 MES 工单进度数据失真的根因是**工序间流转靠人工口报**。理论上 RFID 工位通道闸 + MES 双向集成可以让进度数据从 70% 准提到 99%，但这套方案对**工艺路线稳定性、MES 接口可用性、车间金属环境**有较高前置要求。AssetaGuard 当前的策略是：**先把"工装借用 + 资产盘点 + 物资台账"这一层做扎实**，让客户用 RFID 立刻收益；同时与少数制造业试点客户共建 WIP / MES 集成的完整方案。

## 二、为什么 MES 工单进度数据失真

主流 MES 工单进度的来源是工人在工位终端"扫工单条码 → 报工"。问题在：

- 真实工序流转 1 小时，报工动作 30 秒，工人会**攒着报**
- 报错容易被改，但没有人审
- 跨工位件找不到、放错位 —— 系统不知道，直到下游报缺件

**结果：MES 看到的"在制品分布"和实际不一致**，调度全凭经验。这是制造业普遍痛点，但解决它需要的不是"再加一个扫码动作"，而是让流转**自动记录**。

## 三、RFID + MES 的技术可能性（探索方向）

如果要做完整的 WIP 追踪，技术架构上需要：

### 3.1 托盘策略（不是工件贴标）

工件本身可能要打磨、焊接、热处理，**贴标会被破坏**。所以贴在**托盘 / 周转箱**上：
- 一个托盘对应一批工件（10–100 件不等）
- 托盘 RFID 标签全寿命使用
- 工件本身不动，跟着托盘走

### 3.2 工位通道闸自动读取（路线图）

每个工位入口 / 出口装 RFID 通道闸（约 1 米宽，单点 1.5–3 万元）：
- 托盘进 = 工序开始（自动报工）
- 托盘出 = 工序完工
- 数据 0.5 秒推 MES

**这套硬件 + 软件方案 AssetaGuard 当前没有内置**，需要根据客户车间实际工位布局做设计与联调。

### 3.3 MES 实时双向集成（路线图）

需要 MES 提供：
- 拉取当前工单工艺路线
- 推送工序进度回写
- 异常事件回调

AssetaGuard 当前与 ERP（用友 / 金蝶 / 自研）走标准 REST API + CSV 导入导出做账物对齐；**MES 实时集成不在当前产品规划范围内**，需要项目化定制。

## 四、落地这件事真正需要的前置依赖

如果你的工厂在评估完整的 WIP / MES + RFID 方案，请先评估：

| 前置依赖 | 是否就绪 | 说明 |
| --- | --- | --- |
| 工艺路线 3 个月内不大改 | ⚠️ 关键 | 通道闸点位会变，频繁产线调整不适合 |
| MES 系统有可用接口 | ⚠️ 关键 | 标准 MES（QAD/Plex/SAP DMC）有 API；自研 MES 要双方对接 2–4 周 |
| 车间环境支持 RFID | ⚠️ 关键 | 金属密集 / 高温 / 强电磁需要专用标签 + 实测 |
| 试点产线选型 | 推荐 | 先 5 工位 → 1 条产线 → 全厂 |
| 工人配合机制 | 推荐 | 培训 + 报工 = 计件依据绑定 |

**前 3 项缺任何一项，WIP/MES 完整闭环就成本高、风险大**。建议先从中层能力（工装借用 + 资产盘点 + 物资台账）切入，3–6 个月稳定后再评估顶层方案。
